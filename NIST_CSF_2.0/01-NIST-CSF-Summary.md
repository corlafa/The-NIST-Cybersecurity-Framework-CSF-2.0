
# 🛡️ The NIST Cybersecurity Framework (CSF) 2.0 Summary

เอกสารฉบับนี้สรุปความแตกต่างและองค์ประกอบสำคัญของ **NIST CSF 2.0** **ตามเข้าใจส่วนตัวของผู้เขียน** เพื่อเป็นแนวทางในการจัดการและลดความเสี่ยงด้านความปลอดภัยทางไซเบอร์สำหรับองค์กรทุกขนาด

## 1. วิวัฒนาการ (Evolution)
เปรียบเทียบความเปลี่ยนแปลงสำคัญเพื่อให้เห็นภาพรวมที่ชัดเจนขึ้น

| หัวข้อเปรียบเทียบ | Version 1.0/1.1 | Version 2.0 |
| :--- | :--- | :--- |
| **ชื่อเรียก** | เน้นโครงสร้างพื้นฐานสำคัญ (Critical Infrastructure) | **NIST CSF (ตัดคำว่า Critical Infrastructure ออก)** |
| **ฟังก์ชันหลัก** | 5 Functions (ID, PR, DE, RS, RC) | **6 Functions (เพิ่ม GOVERN เข้ามา)** |
| **กลุ่มเป้าหมาย** | หน่วยงานโครงสร้างพื้นฐาน | **ทุกองค์กร** (SMEs, NGO, รัฐ, เอกชน) |
| **จุดเน้น** | การปฏิบัติการด้านความปลอดภัย | นโยบาย กลยุทธ์ และการสนับสนุนจากผู้บริหาร |

## 2. ภาพรวมและเป้าหมาย (Overview)

<details>
<summary><b>🎯 2.1 เป้าหมายหลัก (คลิกเพื่อดูรายละเอียด)</b></summary>

การให้แนวทางแก่หน่วยงานในการจัดการและลดความเสี่ยง โดยมีจุดเด่นคือ:
* **ภาษากลาง (Common Language):** สื่อสารตรงกันตั้งแต่ฝ่ายไอทีถึงบอร์ดบริหาร
* **Profiles:** เครื่องมือประเมินจุดยืน (Current) และเป้าหมาย (Target)
* **การจัดลำดับความสำคัญ:** เลือกทำสิ่งที่คุ้มค่าและสอดคล้องกับงบประมาณ
* **ความยืดหยุ่น:** ไม่ใช่ข้อบังคับ แต่เน้นที่ "ผลลัพธ์ที่ควรจะเป็น" (Outcomes)
</details>

<details>
<summary><b>👥 2.2 กลุ่มเป้าหมาย (Audience)</b></summary>

* **กลุ่มองค์กร:** ทุกขนาด (SME จนถึงระดับชาติ) และทุกระดับความพร้อมเทคนิค
* **บุคลากรภายใน:**
  * *ผู้บริหาร:* ตัดสินใจเชิงกลยุทธ์/งบประมาณ
  * *ผู้จัดการ:* นำนโยบายไปปฏิบัติและติดตามผล
  * *ผู้เชี่ยวชาญเทคนิค:* ติดตั้งและควบคุมระบบ
  * *ฝ่ายสนับสนุน:* จัดซื้อ, กฎหมาย, HR และผู้ตรวจสอบ
</details>

## 3. องค์ประกอบหลัก (CSF 2.0 Core)
Core แบ่งลำดับชั้นเป็น: **Functions** (กิจกรรมหลัก) > **Categories** (กลุ่มย่อย) > **Subcategories** (ผลลัพธ์เฉพาะเจาะจง)
<p align="center">
  <img src="https://github.com/user-attachments/assets/c8639474-d834-4b00-8f5f-0f0621991d74" width="640">
</p>

### 🔴 6 Functions สำคัญ
| Function | วัตถุประสงค์ | กิจกรรมหลัก |
| :--- | :--- | :--- |
| **1. GOVERN (GV)** | กำหนดทิศทางและนโยบาย | บริบทองค์กร, กลยุทธ์ความเสี่ยง, Supply Chain, บทบาทหน้าที่ |
| **2. IDENTIFY (ID)** | เข้าใจทรัพยากรและความเสี่ยง | สำรวจสินทรัพย์ (Asset), ประเมินความเสี่ยง (Risk Assessment) |
| **3. PROTECT (PR)** | ป้องกันและลดผลกระทบ | การจัดการอัตลักษณ์ (IAM), การสร้างความตระหนักรู้, ความปลอดภัยข้อมูล |
| **4. DETECT (DE)** | ตรวจพบความผิดปกติ | ตรวจสอบต่อเนื่อง (Monitoring), วิเคราะห์เหตุการณ์ไม่พึงประสงค์ |
| **5. RESPOND (RS)** | รับมือเมื่อเกิดเหตุ | บริหารจัดการ Incident, วิเคราะห์เชิงลึก, บรรเทาผลกระทบ, สื่อสาร |
| **6. RECOVER (RC)** | ฟื้นฟูระบบให้ปกติ | ทำตามแผนกู้คืน, ตรวจสอบความถูกต้องข้อมูล, รายงานความคืบหน้า |

## 4. เครื่องมือประเมิน (Profiles & Tiers)

### 📋 4.1 CSF Profiles
คือกลไกอธิบายสถานะ แบ่งเป็น:
* **Current Profile:** สิ่งที่ทำอยู่ในปัจจุบัน
* **Target Profile:** เป้าหมายที่ต้องการไปให้ถึง
* **Community Profile:** โปรไฟล์มาตรฐานสำหรับกลุ่มธุรกิจเดียวกัน

> **ขั้นตอนการทำงาน:** กำหนดขอบเขต > รวบรวมข้อมูล > สร้างโปรไฟล์ > **วิเคราะห์ช่องว่าง (Gap Analysis)** > ดำเนินการแก้ไข

### 🪜 4.2 CSF Tiers
ใช้ระบุความเข้มงวดของกระบวนการ (Benchmark):
1. **Tier 1 (Partial):** เริ่มต้น/เฉพาะหน้า
2. **Tier 2 (Risk-Informed):** รับรู้แต่ยังไม่ครอบคลุม
3. **Tier 3 (Repeatable):** มีมาตรฐานและทำสม่ำเสมอ
4. **Tier 4 (Adaptive):** ปรับตัวตามภัยคุกคามใหม่ๆ ได้ทันที

## 5. การสื่อสารและการบูรณาการ (Integration)

<details>
<summary><b>🗣️ การไหลเวียนข้อมูล (Risk Communication)</b></summary>

* **ระดับบริหาร:** กำหนด Risk Appetite และลำดับความสำคัญ
* **ระดับจัดการ:** ประสานงานสร้าง Profiles และติดตามผล
* **ระดับปฏิบัติการ:** รายงานความคืบหน้าและแจ้งปัญหาหน้างาน
</details>

<details>
<summary><b>🔗 บูรณาการกับโปรแกรมอื่น (ERM)</b></summary>

* **Privacy Risks:** ใช้คู่กับ NIST Privacy Framework (เรื่อง Data Breach)
* **Supply Chain Risks:** เน้นความสำคัญของ C-SCRM
* **Emerging Tech (AI):** อ้างอิงร่วมกับ NIST AI RMF
</details>
