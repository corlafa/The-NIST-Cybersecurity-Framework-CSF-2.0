<summary>📂 1. GOVERN (GV) - การกำกับดูแล</summary>

# 🏛️ Function: GOVERN (GV)

**นิยาม:** กลยุทธ์การบริหารจัดการความเสี่ยงด้านความปลอดภัยทางไซเบอร์ ความคาดหวัง และนโยบายขององค์กรได้รับการจัดทำ สื่อสาร และเฝ้าติดตาม 

---

## 🌐 หมวดหมู่: Organizational Context (GV.OC)
**คำอธิบาย:** การทำความเข้าใจบริบทต่างๆ เช่น พันธกิจ ความคาดหวังของผู้มีส่วนได้ส่วนเสีย ข้อกำหนดทางกฎหมาย และความเชื่อมโยงของหน่วยงาน เพื่อใช้ประกอบการตัดสินใจด้านความเสี่ยง 

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **GV.OC-01** | พันธกิจขององค์กรต้องเป็นที่เข้าใจชัดเจน เพื่อใช้กำหนดทิศทางการจัดการความเสี่ยงไซเบอร์ |
| **GV.OC-02** | ความต้องการและความคาดหวังของผู้มีส่วนได้ส่วนเสียทั้งภายในและภายนอก ต้องถูกนำมาพิจารณา  |
| **GV.OC-03** | ข้อกำหนดทางกฎหมาย กฎระเบียบ และสัญญาจ้าง (รวมถึงเรื่องความเป็นส่วนตัว) ต้องได้รับการจัดการ  |
| **GV.OC-04** | วัตถุประสงค์และบริการที่ผู้มีส่วนได้ส่วนเสียภายนอกต้องพึ่งพาจากองค์กร ต้องมีการสื่อสารให้ชัดเจน |
| **GV.OC-05** | บริการหรือผลลัพธ์ที่องค์กรต้องไปพึ่งพาจากหน่วยงานอื่น ต้องมีการระบุและสื่อสารให้ทราบทั่วกัน  |

---
## 🎯 หมวดหมู่: Risk Management Strategy (GV.RM)
**คำอธิบาย:** การกำหนดลำดับความสำคัญ ข้อจำกัด ระดับความเสี่ยงที่ยอมรับได้ (Risk Appetite/Tolerance) และข้อสมมติฐานต่างๆ เพื่อใช้สนับสนุนการตัดสินใจด้านการดำเนินงานอย่างมีประสิทธิภาพ 

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **GV.RM-01** | วัตถุประสงค์ในการจัดการความเสี่ยงได้รับการจัดทำและเห็นชอบโดยผู้มีส่วนได้ส่วนเสีย |
| **GV.RM-02** | เกณฑ์ระดับความเสี่ยงที่ยอมรับได้ (Risk Appetite & Tolerance) ถูกกำหนด สื่อสาร และจัดเก็บอย่างเป็นระบบ  |
| **GV.RM-03** | กิจกรรมและผลลัพธ์ของการจัดการความเสี่ยงไซเบอร์ถูกรวมเข้ากับกระบวนการบริหารความเสี่ยงระดับองค์กร (ERM)  |
| **GV.RM-04** | ทิศทางเชิงกลยุทธ์ที่ระบุแนวทางการตอบสนองต่อความเสี่ยงที่เหมาะสมถูกจัดทำและสื่อสาร |
| **GV.RM-05** | มีการสร้างช่องทางการสื่อสารเรื่องความเสี่ยงไซเบอร์ทั่วทั้งองค์กร รวมถึงความเสี่ยงจากคู่ค้าและบุคคลที่สาม  |
| **GV.RM-06** | มีวิธีการมาตรฐานในการคำนวณ บันทึก จัดกลุ่ม และจัดลำดับความสำคัญของความเสี่ยงไซเบอร์  |
| **GV.RM-07** | โอกาสเชิงกลยุทธ์ (Positive Risks) ถูกระบุและนำเข้าร่วมในการสนทนาด้านความเสี่ยงไซเบอร์ขององค์กร  |

---
## 👥 หมวดหมู่: Roles, Responsibilities, and Authorities (GV.RR)
**คำอธิบาย:** การกำหนดบทบาท ความรับผิดชอบ และอำนาจหน้าที่ด้านความมั่นคงปลอดภัยไซเบอร์ เพื่อส่งเสริมความรับผิดชอบ การประเมินผลการดำเนินงาน และการปรับปรุงอย่างต่อเนื่อง

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **GV.RR-01** | ผู้นำองค์กรต้องรับผิดชอบต่อความเสี่ยงไซเบอร์ และส่งเสริมวัฒนธรรมที่ตระหนักถึงความเสี่ยง มีจริยธรรม และพัฒนาต่อเนื่อง |
| **GV.RR-02** | บทบาท ความรับผิดชอบ และอำนาจหน้าที่ในการจัดการความเสี่ยงไซเบอร์ถูกกำหนด สื่อสาร และบังคับใช้ |
| **GV.RR-03** | จัดสรรทรัพยากรให้เพียงพอและสอดคล้องกับกลยุทธ์ความเสี่ยง บทบาทหน้าที่ และนโยบายขององค์กร |
| **GV.RR-04** | ความมั่นคงปลอดภัยไซเบอร์ถูกรวมเข้าเป็นส่วนหนึ่งของแนวทางปฏิบัติพื้นฐานในฝ่ายทรัพยากรบุคคล (HR)  |

---

## 📜 หมวดหมู่: Policy (GV.PO)
**คำอธิบาย:** การจัดทำ สื่อสาร และบังคับใช้นโยบายความมั่นคงปลอดภัยไซเบอร์ขององค์กร 

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **GV.PO-01** | จัดทำนโยบายบริหารความเสี่ยงโดยอิงจากบริบท กลยุทธ์ และลำดับความสำคัญขององค์กร พร้อมทั้งสื่อสารและบังคับใช้ |
| **GV.PO-02** | ทบทวนและอัปเดตนโยบายให้ทันสมัยตามการเปลี่ยนแปลงของข้อกำหนด ภัยคุกคาม เทคโนโลยี และพันธกิจขององค์กร  |

---

## ⚖️ หมวดหมู่: Oversight (GV.OV)
**คำอธิบาย:** การนำผลลัพธ์จากการจัดการความเสี่ยงทั่วทั้งองค์กรมาใช้เพื่อแจ้ง ปรับปรุง และปรับเปลี่ยนกลยุทธ์การจัดการความเสี่ยง 

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **GV.OV-01** | ทบทวนผลลัพธ์ของกลยุทธ์การจัดการความเสี่ยงเพื่อนำข้อมูลมาใช้ปรับทิศทางขององค์กร  |
| **GV.OV-02** | ทบทวนและปรับกลยุทธ์ให้ครอบคลุมความเสี่ยงและข้อกำหนดทั้งหมดขององค์กร  |
| **GV.OV-03** | ประเมินและทบทวนประสิทธิภาพการจัดการความเสี่ยงเพื่อหาจุดที่ต้องปรับเปลี่ยน  |

---
## ⛓️ หมวดหมู่: Cybersecurity Supply Chain Risk Management (GV.SC)
**คำอธิบาย:** กระบวนการจัดการความเสี่ยงในห่วงโซ่อุปทานด้านไซเบอร์ได้รับการระบุ จัดทำ บริหารจัดการ เฝ้าติดตาม และปรับปรุงโดยผู้มีส่วนได้ส่วนเสียในองค์กร

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **GV.SC-01** | โปรแกรม กลยุทธ์ วัตถุประสงค์ นโยบาย และกระบวนการจัดการความเสี่ยงโซ่อุปทานได้รับการจัดทำและเห็นชอบร่วมกัน |
| **GV.SC-02** | บทบาทและความรับผิดชอบด้านไซเบอร์สำหรับผู้จัดจำหน่าย (Suppliers) ลูกค้า และพาร์ทเนอร์ได้รับการจัดทำและประสานงานกัน |
| **GV.SC-03** | การจัดการความเสี่ยงโซ่อุปทานถูกรวมเข้ากับการจัดการความเสี่ยงองค์กร (ERM) และกระบวนการประเมินความเสี่ยงหลัก |
| **GV.SC-04** | ผู้จัดจำหน่ายและคู่ค้าได้รับการระบุและจัดลำดับความสำคัญตามความสำคัญต่อองค์กร (Criticality) |
| **GV.SC-05** | ข้อกำหนดในการจัดการความเสี่ยงไซเบอร์ถูกระบุและรวมเข้าในสัญญาหรือข้อตกลงกับผู้จัดจำหน่ายและบุคคลที่สาม |
| **GV.SC-06** | มีการวางแผนและตรวจสอบประวัติ (Due Diligence) เพื่อลดความเสี่ยงก่อนเริ่มความสัมพันธ์ทางธุรกิจกับคู่ค้าใหม่ |
| **GV.SC-07** | ความเสี่ยงจากคู่ค้า ผลิตภัณฑ์ และบริการได้รับการประเมิน บันทึก และเฝ้าติดตามตลอดช่วงเวลาที่มีความสัมพันธ์กัน |
| **GV.SC-08** | คู่ค้าและบุคคลที่สามที่เกี่ยวข้องถูกดึงเข้ามามีส่วนร่วมในแผนการเตรียมพร้อม การตอบสนอง และการฟื้นฟูจากเหตุการณ์ |
| **GV.SC-09** | แนวปฏิบัติความปลอดภัยโซ่อุปทานถูกตรวจสอบประสิทธิภาพตลอดวงจรชีวิต (Life cycle) ของผลิตภัณฑ์และบริการเทคโนโลยี |
| **GV.SC-10** | แผนจัดการความเสี่ยงโซ่อุปทานรวมถึงมาตรการรองรับสำหรับกิจกรรมที่จะเกิดขึ้นหลังสิ้นสุดสัญญาจ้างหรือการเป็นพาร์ทเนอร์ |
</details>

<summary>📂 2. IDENTIFY (ID) - การระบุ</summary>

# 🔍 Function: IDENTIFY (ID)

**นิยาม:** การทำความเข้าใจความเสี่ยงด้านความปลอดภัยทางไซเบอร์ในปัจจุบันขององค์กร เพื่อวางรากฐานในการบริหารจัดการ

---
## 📦 หมวดหมู่: Asset Management (ID.AM)
**คำอธิบาย:** การระบุและจัดการสินทรัพย์ (ข้อมูล, ฮาร์ดแวร์, ซอฟต์แวร์, ระบบ, บริการ และบุคคล) ให้สอดคล้องกับความสำคัญต่อภารกิจขององค์กร

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **ID.AM-01** | จัดทำและบำรุงรักษาบัญชีรายชื่อฮาร์ดแวร์ทั้งหมดที่องค์กรดูแล |
| **ID.AM-02** | จัดทำและบำรุงรักษาบัญชีรายชื่อซอฟต์แวร์ บริการ และระบบต่างๆ |
| **ID.AM-03** | ทำแผนผังการไหลของข้อมูล (Data Flow) ทั้งภายในและภายนอกเครือข่าย |
| **ID.AM-04** | จัดทำบัญชีรายชื่อบริการที่ได้รับจากคู่ค้าหรือผู้จัดจำหน่าย |
| **ID.AM-05** | จัดลำดับความสำคัญของสินทรัพย์ตามผลกระทบต่อภารกิจและทรัพยากรที่มี |
| **ID.AM-07** | จัดการบัญชีข้อมูลและ Metadata สำหรับข้อมูลประเภทที่กำหนดไว้ |
| **ID.AM-08** | บริหารจัดการวงจรชีวิต (Lifecycle) ของระบบ ฮาร์ดแวร์ และซอฟต์แวร์ทั้งหมด |

---

## ⚖️ หมวดหมู่: Risk Assessment (ID.RA)
**คำอธิบาย:** การประเมินเพื่อให้องค์กรเข้าใจความเสี่ยงไซเบอร์ที่อาจเกิดกับสินทรัพย์และบุคลากร

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **ID.RA-01** | ระบุและบันทึกช่องโหว่ (Vulnerabilities) ที่พบในสินทรัพย์ |
| **ID.RA-02** | รับข้อมูลข่าวสารด้านภัยคุกคาม (Threat Intelligence) จากแหล่งที่เชื่อถือได้ |
| **ID.RA-03** | ระบุและบันทึกภัยคุกคาม (Threats) ทั้งจากภายในและภายนอกองค์กร |
| **ID.RA-04** | วิเคราะห์โอกาสและผลกระทบหากภัยคุกคามโจมตีผ่านช่องโหว่ที่พบ |
| **ID.RA-05** | นำข้อมูลทั้งหมดมาวิเคราะห์เพื่อจัดลำดับความสำคัญในการตอบสนองความเสี่ยง |
| **ID.RA-06** | วางแผนและเลือกวิธีการตอบสนองต่อความเสี่ยง พร้อมติดตามผล |
| **ID.RA-07** | จัดการกรณีที่มีการเปลี่ยนแปลงหรือข้อยกเว้น (Exceptions) ในการรับความเสี่ยง |
| **ID.RA-08** | สร้างกระบวนการรับแจ้งและวิเคราะห์การเปิดเผยช่องโหว่จากภายนอก |
| **ID.RA-09** | ตรวจสอบความปลอดภัยของฮาร์ดแวร์และซอฟต์แวร์ก่อนการจัดซื้อมาใช้งาน |
| **ID.RA-10** | ประเมินความปลอดภัยของคู่ค้า (Suppliers) รายสำคัญก่อนเริ่มการจัดซื้อ |

---

## 📈 หมวดหมู่: Improvement (ID.IM)
**คำอธิบาย:** การระบุจุดที่ควรปรับปรุงในกระบวนการจัดการความเสี่ยงไซเบอร์อย่างต่อเนื่อง

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **ID.IM-01** | ค้นหาจุดที่ต้องปรับปรุงจากการประเมินผลการดำเนินงานที่ผ่านมา |
| **ID.IM-02** | ปรับปรุงระบบจากการทดสอบความปลอดภัยและการซ้อมแผนรับมือเหตุการณ์ |
| **ID.IM-03** | ระบุจุดอ่อนและแนวทางการพัฒนาจากขั้นตอนการทำงานตามปกติประจำวัน |
| **ID.IM-04** | จัดทำและปรับปรุงแผนรับมือเหตุการณ์ (Incident Response Plan) ให้ทันสมัยเสมอ |

</details>

<details>
<summary>📂 3. PROTECT (PR) - การป้องกัน</summary>

# 🛡️ Function: PROTECT (PR)

**นิยาม:** การใช้มาตรการรักษาความปลอดภัยเพื่อจัดการและควบคุมความเสี่ยงด้านไซเบอร์ขององค์กร

---
## 🔑 หมวดหมู่: Identity Management, Authentication, and Access Control (PR.AA)
**คำอธิบาย:** การจำกัดการเข้าถึงสินทรัพย์ทางกายภาพและทางตรรกะเฉพาะผู้ใช้ บริการ และฮาร์ดแวร์ที่ได้รับอนุญาตเท่านั้น โดยบริหารจัดการตามระดับความเสี่ยง

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **PR.AA-01** | อัตลักษณ์ (Identities) และข้อมูลยืนยันตัวตน (Credentials) สำหรับผู้ใช้ บริการ และฮาร์ดแวร์ได้รับการจัดการโดยองค์กร |
| **PR.AA-02** | อัตลักษณ์ได้รับการพิสูจน์และผูกพันกับข้อมูลยืนยันตัวตนตามบริบทของการใช้งาน |
| **PR.AA-03** | ผู้ใช้ บริการ และฮาร์ดแวร์ต้องผ่านการตรวจสอบสิทธิ์ (Authenticated) ก่อนเข้าใช้งาน |
| **PR.AA-04** | ข้อมูลการยืนยันตัวตนได้รับการปกป้อง ส่งต่อ และตรวจสอบความถูกต้องอย่างปลอดภัย |
| **PR.AA-05** | สิทธิ์การเข้าถึงและการอนุญาตถูกกำหนดตามนโยบาย โดยใช้หลักการสิทธิ์ขั้นต่ำ (Least Privilege) และการแยกหน้าที่ (Separation of Duties) |
| **PR.AA-06** | การเข้าถึงสถานที่ตั้งของสินทรัพย์ (Physical Access) ได้รับการจัดการ ตรวจสอบ และบังคับใช้ตามระดับความเสี่ยง |

---

## 🎓 หมวดหมู่: Awareness and Training (PR.AT)
**คำอธิบาย:** บุคลากรขององค์กรได้รับการสร้างความตระหนักรู้และฝึกอบรมด้านความปลอดภัยไซเบอร์ เพื่อให้สามารถปฏิบัติหน้าที่ได้อย่างปลอดภัย

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **PR.AT-01** | บุคลากรทั่วไปได้รับการอบรมเพื่อให้มีกความรู้และทักษะในการปฏิบัติงานโดยคำนึงถึงความเสี่ยงไซเบอร์ |
| **PR.AT-02** | บุคลากรในบทบาทเฉพาะทางได้รับการอบรมทักษะเชิงลึกที่เกี่ยวข้องกับหน้าที่และความรับผิดชอบด้านความปลอดภัย |

---

## 💾 หมวดหมู่: Data Security (PR.DS)
**คำอธิบาย:** การจัดการข้อมูลตามกลยุทธ์ความเสี่ยงเพื่อรักษาความลับ (Confidentiality), ความถูกต้อง (Integrity) และความพร้อมใช้งาน (Availability)

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **PR.DS-01** | ข้อมูลขณะจัดเก็บ (Data-at-rest) ได้รับการปกป้อง |
| **PR.DS-02** | ข้อมูลขณะรับส่ง (Data-in-transit) ได้รับการปกป้อง |
| **PR.DS-10** | ข้อมูลขณะใช้งาน (Data-in-use) ได้รับการปกป้อง |
| **PR.DS-11** | ข้อมูลได้รับการสำรอง (Backup) ปกป้อง บำรุงรักษา และทดสอบการกู้คืน |

---

## 💻 หมวดหมู่: Platform Security (PR.PS)
**คำอธิบาย:** การจัดการฮาร์ดแวร์ ซอฟต์แวร์ และบริการของแพลตฟอร์ม (ทั้งกายภาพและเสมือน) เพื่อรักษาความปลอดภัยของระบบ

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **PR.PS-01** | จัดทำและใช้แนวทางปฏิบัติการจัดการการตั้งค่าระบบ (Configuration Management) |
| **PR.PS-02** | บำรุงรักษา เปลี่ยนแปลง หรือลบซอฟต์แวร์ออกจากระบบตามระดับความเสี่ยง |
| **PR.PS-03** | บำรุงรักษา เปลี่ยนแปลง หรือลบฮาร์ดแวร์ออกจากระบบตามระดับความเสี่ยง |
| **PR.PS-04** | จัดทำบันทึกเหตุการณ์ (Log Records) และทำให้พร้อมสำหรับการตรวจสอบอย่างต่อเนื่อง |
| **PR.PS-05** | ป้องกันการติดตั้งและรันซอฟต์แวร์ที่ไม่ได้รับอนุญาต |
| **PR.PS-06** | รวมแนวปฏิบัติการพัฒนาซอฟต์แวร์ที่ปลอดภัย (Secure SDLC) เข้าในวงจรการพัฒนา |

---

## 🏗️ หมวดหมู่: Technology Infrastructure Resilience (PR.IR)
**คำอธิบาย:** การจัดการสถาปัตยกรรมความปลอดภัยตามกลยุทธ์ความเสี่ยง เพื่อปกป้องสินทรัพย์และสร้างความยืดหยุ่นให้องค์กร

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **PR.IR-01** | เครือข่ายและสภาพแวดล้อมได้รับการป้องกันจากการเข้าถึงและการใช้งานที่ไม่ได้รับอนุญาต |
| **PR.IR-02** | สินทรัพย์ทางเทคโนโลยีได้รับการปกป้องจากภัยคุกคามทางสิ่งแวดล้อม (เช่น ภัยธรรมชาติ) |
| **PR.IR-03** | กลไกความยืดหยุ่นได้รับการติดตั้งเพื่อให้ระบบทำงานได้ทั้งในสถานการณ์ปกติและวิกฤต |
| **PR.IR-04** | รักษากำลังทรัพยากร (Capacity) ให้เพียงพอเพื่อให้ระบบพร้อมใช้งานเสมอ |

</details>

<summary>📂 4. DETECT (DE) - การตรวจจับ</summary>

# 🔍 Function: DETECT (DE)

**นิยาม:** การตรวจพบและวิเคราะห์การโจมตีไซเบอร์หรือเหตุการณ์ละเมิดที่อาจเกิดขึ้นได้อย่างรวดเร็ว

---
## ⏲️ หมวดหมู่: Continuous Monitoring (DE.CM)
**คำอธิบาย:** การเฝ้าระวังสินทรัพย์อย่างต่อเนื่องเพื่อค้นหาความผิดปกติ (Anomalies), สัญญาณการบุกรุก (Indicators of Compromise) และเหตุการณ์ที่ไม่พึงประสงค์อื่นๆ

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **DE.CM-01** | เครือข่ายและบริการเครือข่ายได้รับการเฝ้าระวังเพื่อค้นหาเหตุการณ์ที่อาจเป็นอันตราย |
| **DE.CM-02** | สภาพแวดล้อมทางกายภาพได้รับการเฝ้าระวังเพื่อค้นหาเหตุการณ์ที่อาจเป็นอันตราย |
| **DE.CM-03** | กิจกรรมของบุคลากรและการใช้เทคโนโลยีได้รับการเฝ้าระวังเพื่อค้นหาความผิดปกติ |
| **DE.CM-06** | กิจกรรมและบริการของผู้ให้บริการภายนอก (External Service Provider) ได้รับการเฝ้าระวัง |
| **DE.CM-09** | ฮาร์ดแวร์, ซอฟต์แวร์, Runtime Environments และข้อมูล ได้รับการเฝ้าระวังอย่างต่อเนื่อง |

---

## 🔬 หมวดหมู่: Adverse Event Analysis (DE.AE)
**คำอธิบาย:** การนำความผิดปกติหรือสัญญาณการบุกรุกที่พบ มาวิเคราะห์เพื่อระบุลักษณะของเหตุการณ์และตรวจจับสถานะการเกิดเหตุการณ์ละเมิดความปลอดภัย (Incidents)

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **DE.AE-02** | วิเคราะห์เหตุการณ์ที่อาจเป็นอันตรายเพื่อทำความเข้าใจพฤติกรรมและกิจกรรมที่เกี่ยวข้อง |
| **DE.AE-03** | นำข้อมูลจากหลายแหล่งมาวิเคราะห์หาความเชื่อมโยง (Correlation) เพื่อความแม่นยำ |
| **DE.AE-04** | ประเมินและทำความเข้าใจขอบเขต (Scope) รวมถึงผลกระทบที่คาดว่าจะเกิดขึ้นจากเหตุการณ์ |
| **DE.AE-06** | ข้อมูลเกี่ยวกับเหตุการณ์ที่เป็นอันตรายได้รับการส่งต่อให้เจ้าหน้าที่และเครื่องมือที่มีอำนาจหน้าที่ |
| **DE.AE-07** | นำข้อมูลข่าวกรองภัยคุกคาม (Cyber Threat Intelligence) และข้อมูลบริบทอื่นๆ มาบูรณาการในการวิเคราะห์ |
| **DE.AE-08** | ประกาศสถานะ "เหตุการณ์ละเมิด" (Incidents) เมื่อเหตุการณ์นั้นเข้าเงื่อนไขตามเกณฑ์ที่กำหนดไว้ |
</details>

<summary>📂 5. RESPOND (RS) - การตอบสนอง</summary>
  
# 🚩 Function: RESPOND (RS)

**นิยาม:** การดำเนินการจัดการกับเหตุการณ์ละเมิดความปลอดภัยทางไซเบอร์ที่ตรวจพบ เพื่อยับยั้งและลดผลกระทบ

---
## 📋 หมวดหมู่: Incident Management (RS.MA)
**คำอธิบาย:** การบริหารจัดการมาตรการตอบสนองต่อเหตุการณ์ภัยคุกคามไซเบอร์ที่ตรวจพบอย่างเป็นระบบ

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **RS.MA-01** | ดำเนินการตามแผนรับมือเหตุการณ์ (Incident Response Plan) โดยประสานงานกับผู้เกี่ยวข้องเมื่อมีการประกาศเหตุการณ์ |
| **RS.MA-02** | ตรวจสอบ คัดกรอง (Triage) และยืนยันความถูกต้องของรายงานเหตุการณ์ |
| **RS.MA-03** | จัดกลุ่มประเภทและลำดับความสำคัญของเหตุการณ์ที่เกิดขึ้น |
| **RS.MA-04** | ส่งต่อเหตุการณ์ไปยังผู้มีอำนาจตัดสินใจหรือผู้เชี่ยวชาญระดับสูงตามความเหมาะสม |
| **RS.MA-05** | ใช้เกณฑ์การพิจารณาเพื่อเริ่มต้นเข้าสู่กระบวนการฟื้นฟูระบบ (Recovery) |

---

## 🔍 หมวดหมู่: Incident Analysis (RS.AN)
**คำอธิบาย:** การสืบสวนหาสาเหตุเพื่อให้การตอบสนองมีประสิทธิภาพ และสนับสนุนกิจกรรมด้านนิติวิทยาศาสตร์ดิจิทัล (Forensics)

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **RS.AN-03** | วิเคราะห์หาสิ่งที่เกิดขึ้นระหว่างเกิดเหตุและระบุสาเหตุที่แท้จริง (Root Cause) ของเหตุการณ์ |
| **RS.AN-06** | บันทึกกิจกรรมที่ทำระหว่างการสืบสวน โดยรักษาความถูกต้องสมบูรณ์และแหล่งที่มาของบันทึกไว้อย่างดี |
| **RS.AN-07** | เก็บรวบรวมข้อมูลและ Metadata ของเหตุการณ์ โดยรักษาความสมบูรณ์ของข้อมูลเพื่อใช้เป็นหลักฐาน |
| **RS.AN-08** | ประเมินและยืนยันขนาดความรุนแรง (Magnitude) ของเหตุการณ์ที่เกิดขึ้น |

---

## 📢 หมวดหมู่: Incident Response Reporting and Communication (RS.CO)
**คำอธิบาย:** การประสานงานและแจ้งเหตุให้ผู้มีส่วนได้ส่วนเสียทั้งภายในและภายนอกทราบตามข้อกำหนดทางกฎหมายหรือนโยบาย

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **RS.CO-02** | แจ้งเหตุการณ์ให้ผู้มีส่วนได้ส่วนเสียทั้งภายในและภายนอกทราบตามลำดับความสำคัญ |
| **RS.CO-03** | แบ่งปันข้อมูลที่จำเป็นให้กับผู้มีส่วนได้ส่วนเสียที่ได้รับมอบหมาย |

---

## 🛡️ หมวดหมู่: Incident Mitigation (RS.MI)
**คำอธิบาย:** กิจกรรมที่ทำเพื่อป้องกันการแพร่กระจายของเหตุการณ์และลดผลกระทบที่เกิดขึ้น

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **RS.MI-01** | จำกัดวงความเสียหาย (Containment) เพื่อไม่ให้เหตุการณ์แพร่กระจายไปยังส่วนอื่น |
| **RS.MI-02** | กำจัดต้นตอของเหตุการณ์ (Eradication) ออกจากระบบให้หมดสิ้น |


</details>

<summary>📂 6. RECOVER (RC) - การฟื้นฟู</summary>

# 🔄 Function: RECOVER (RC)

**นิยาม:** การฟื้นฟูสินทรัพย์และการดำเนินงานที่ได้รับผลกระทบจากเหตุการณ์ละเมิดความปลอดภัยไซเบอร์ให้กลับคืนสู่สภาวะปกติ

---
## 🛠️ หมวดหมู่: Incident Recovery Plan Execution (RC.RP)
**คำอธิบาย:** การดำเนินการฟื้นฟูเพื่อรักษาความพร้อมใช้งานของระบบและบริการที่ได้รับผลกระทบจากเหตุการณ์

| รหัส (ID) | ผลลัพธ์ที่พึงประสงค์ (Subcategory Outcome) |
| :---: | :--- |
| **RC.RP-01** | ดำเนินการตามแผนฟื้นฟูเหตุการณ์ (Recovery Plan) ทันทีที่กระบวนการตอบสนองเหตุการณ์เริ่มต้นขึ้น |
| **RC.RP-02** | เลือกวิธีการฟื้นฟู กำหนดขอบเขต จัดลำดับความสำคัญ และดำเนินการฟื้นฟูตามแผนที่วางไว้ |
| **RC.RP-03** | ตรวจสอบความถูกต้องสมบูรณ์ (Integrity) ของข้อมูลสำรองและสินทรัพย์ที่ใช้ในการฟื้นฟูก่อนนำไปใช้งานจริง |
| **RC.RP-04** | พิจารณาฟังก์ชันหลักที่สำคัญต่อภารกิจ (Critical Mission) เพื่อกำหนดเกณฑ์การดำเนินงานปกติหลังเกิดเหตุ |
| **RC.RP-05** | ตรวจสอบความสมบูรณ์ของสินทรัพย์ที่ฟื้นฟูแล้ว และยืนยันสถานะการทำงานว่ากลับเข้าสู่สภาวะปกติ |
| **RC.RP-06** | ประกาศสิ้นสุดการฟื้นฟูตามเกณฑ์ที่กำหนด และจัดทำเอกสารสรุปเหตุการณ์ให้ครบถ้วน |
